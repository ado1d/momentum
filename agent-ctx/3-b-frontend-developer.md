- **GoalsView**: ViewHeader ("Goals" / "Daily learning goals, weekly targets, monthly ambitions") with Reset dropdown + New goal button. Query: `["goals"]` → `goalsApi.list({ status: "all" })`, all filtering client-side.
  - Summary strip: 3 stat chips — Active, Completed (all time), Completed this week (`dateToKey(new Date(updatedAt)) >= weekStartKey(today)`).
  - Filters: Tabs All | Daily | Weekly | Monthly (segmented via Tabs primitives, no TabsContent) + Active/Completed/Archived status chips (toggle; re-click clears; default Active).
  - GoalCard: category emoji chip, title, period badge (emerald/amber/violet soft), description (line-clamp-1), ProgressBar colored by period with animated width, "N / M unit · P%" tabular-nums, due date chip (`friendlyDay(endDate)`, destructive when overdue), status badges (Done w/ CircleCheck, Archived muted); completed cards get emerald border/soft bg, archived cards muted. Controls: size-11 circular Minus (disabled at 0) / Plus (disabled at target) → optimistic `goalsApi.increment(id, ±1)` (status rules mirrored client-side); "🎉 Goal completed!" toast when crossing to target. Kebab: Edit / Mark complete (`update {progress: target}` + celebration toast) / Archive/Unarchive / Delete (AlertDialog).
  - New/Edit goal Dialog: title, description Textarea, category Select (learning/fitness/career/personal/finance/other with emoji), period segmented with GOAL_PERIODS hints, target number input (min 1) + unit input, start date (default today) + optional end date. Empty state: Target icon + "Set a goal" + "Add sample learning goals" (creates the 2 spec'd samples). Filtered-empty state with "Clear filters".
- Reset menu note: spec referenced `goalsApi.resetPeriod` which does not exist in api.ts (only `resetPeriodProgress()` = reset ALL). Worked around by batching `goalsApi.update(id, { progress: 0 })` per goal of the chosen period (server auto-reverts status to active). Includes daily/weekly/monthly (spec listed daily/weekly; monthly added for completeness since GOAL_PERIODS has three).
- All mutations invalidate `["habits"]`/`["routine"]`/`["goals"]` + `["stats"]` so the dashboard stays fresh. Error handling: per-mutation `toast.error(e.message)`, optimistic rollback via `onMutate` snapshots. Loading = skeleton blocks; error = retry card. 44px touch targets everywhere (size-11 buttons/chips), focus-visible rings, aria-pressed/aria-label on all icon-only controls, tabular-nums, rounded-2xl, subtle shadows, no indigo/blue classes.
